## 3. 连接串（本机开发）

```bash
# .env（前后端仓库根目录 / apps/api/.env）
DATABASE_URL="postgresql://worklog:<PG_APPPASSWORD>@127.0.0.1:5432/worklog?schema=public"
```

真实密码见 `.local/pg-credentials.txt` 的 `PG_APPPASSWORD`，也可以直接用 `.local/api.env`（已按上面格式生成）。

管理连接（超级用户）：

```bash
psql -h 127.0.0.1 -p 5432 -U postgres -d postgres
# 密码见 .local/pg-credentials.txt 的 PG_SUPERPASSWORD
```

## 4. 常用运维命令

```powershell
# 服务状态 / 启停（启停需管理员权限）
Get-Service postgresql-x64-17
Stop-Service postgresql-x64-17
Start-Service postgresql-x64-17
Restart-Service postgresql-x64-17

# 连接应用库
psql -h 127.0.0.1 -U worklog -d worklog

# 库内常用查询
\l                # 列出数据库
\dt               # 列出表
\d work_items     # 查看表结构
\du               # 列出角色

# 备份 / 恢复（-Fc 自定义压缩格式，恢复用 pg_restore）
pg_dump -h 127.0.0.1 -U worklog -Fc -f "D:\backup\worklog-$(Get-Date -Format yyyyMMdd-HHmmss).dump" worklog
pg_restore -h 127.0.0.1 -U worklog -d worklog --clean --if-exists "D:\backup\worklog-20261013-231500.dump"
```

## 6. 注意事项

1. **对外暴露**：`listen_addresses = '*'` 表示监听所有网卡，但**未添加 Windows 防火墙入站规则**，因此默认只有本机能连。如果你要连局域网（例如从手机或另一台机器连本机库），需要同时放开防火墙和 `pg_hba.conf`；反之若想更严格，可把 `listen_addresses` 改成 `localhost` 后重启服务。
2. **`pg_hba.conf`**：`D:\pgsql\data\pg_hba.conf`，默认本机（127.0.0.1/32、::1/128）走 `scram-sha-256`，无需改动。
3. **排序规则**是中文 Windows 默认的 `Chinese (Simplified)_China.936`，中文排序正常；**与线上 Docker `postgres` 镜像（默认 `en_US.utf8` 或 `C.UTF-8`）不一致**，跨环境比较字符串排序时可能有细微差异。若你在意一致性，可以在 Docker Compose 里显式指定 `POSTGRES_INITDB_ARGS="--locale=zh_CN.UTF-8"`，或本机建库时用 `LC_COLLATE` 对齐。
4. **卸载**：`D:\pgsql\uninstall-postgresql.exe`（会移除服务，但**不会**删除数据目录，需手动清理 `D:\pgsql\data`）。
5. **安装包**留在 `D:\project\白狼\.local\downloads\postgresql-17.7-1-windows-x64.exe`（369MB），用于重装/修复，不需要时可直接删除；下载脚本为 `.local\download.js`（本机 schannel 的 TLS 不可用，只能用 Node 下载）。

## 7. 中文 Windows 下的 psql 编码坑（已实测）

数据库本身是 UTF8，中文/emoji/日文读写**均正常**（已实测：`白狼 worklog 中文测试`、`🐺`、`テスト` 全部正确回环）。但**从命令行用 psql 时要避开两个坑**：

### 坑 1：命令行直接传中文 SQL 会报编码错误

```powershell
# ❌ 会失败：错误: 无效的 "UTF8" 编码字节顺序: 0xb0
psql -h 127.0.0.1 -U worklog -d worklog -c "insert into t(note) values ('白狼');"
```

原因：PowerShell 用系统 ANSI 代码页（GBK/936）把参数传给原生程序，字节在到达 psql 之前就已经不是 UTF-8 了。

```powershell
# ✅ 正确做法：把 SQL 写进 UTF-8 文件，再用 -f 执行
$env:PGCLIENTENCODING = 'UTF8'
psql -h 127.0.0.1 -U worklog -d worklog -f .\patch.sql
```

> 本项目的应用代码（Node/Prisma/pg 驱动）始终以 UTF-8 通信，**不受此问题影响**，这只是手工用 psql 时的注意事项。

### 坑 2：psql 的 `\o` / `\i` 遇到含中文的路径会失败

实测 `\o D:/project/白狼/.local/out.txt` 报 `No such file or directory`（psql 用 ANSI 代码页转换了文件名）。而**通过命令行参数传同一个中文路径是正常的**（`psql -f`、`pg_dump -f` 都没问题）。

- 建议：导出/备份文件统一放到**纯 ASCII 路径**（如 `D:\backup`），既避开这个坑，也便于脚本处理。
- 备份工具链已验证：`pg_dump -Fc` 导出成功，`pg_restore -l` 可正常读取归档（Dump Version 1.16-0，gzip 压缩）。
